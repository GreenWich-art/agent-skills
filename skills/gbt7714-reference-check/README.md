# gbt7714-reference-check

中文论文 / 学位论文交稿前的参考文献两件套：**GB/T 7714-2015 著录规范化** +
**链接批量核验（能区分"真死链"和"被反爬"）**。

既是一个 **Agent Skill**（放进 skills 目录，Agent 在核对文献表时自动遵循），
也附带一个可独立运行的命令行核验脚本。

## 这个工具适合你吗？

**适合谁**：写中文学位论文、期刊论文、综述、课程作业的学生与研究者；
需要向中文期刊/学校提交 GB/T 7714 格式参考文献表的任何人；
经常要批量验证一堆文献链接"还活着没有"的人。

**典型场景**：

| 场景 | 它能做什么 |
|---|---|
| 论文要交了，导师说"参考文献按国标改" | 给出 GB/T 7714-2015 著录要点速查 + 8 项交稿前检查清单，逐条对照 |
| 从 Zotero/EndNote 导出的格式总有几处不对劲 | 指出高频错点：文献类型标识、`[引用日期]` 取舍、3 位以上作者写法、西文人名变音字母丢失 |
| 手里有 50 条 URL/DOI/PMID，想知道哪些失效了 | `check_refs.py` 并发核验，分三桶报告：可访问 / 疑似反爬（浏览器能开）/ 疑似失效 |
| 批量核验时把 403 全当成死链删掉了 | 它的核心差异：**能区分真死链和被反爬拦截**（卫健委、万方、NEJM 付费墙都实测过） |

**不适合谁**：需要**从零生成**引文正文（那是写作任务，它只规范文献表）；
写英文论文用 APA/MLA/Vancouver 格式（本工具只覆盖 GB/T 7714）；
需要 Zotero 图形界面样式定制（它只给 CSL 文件级修改指引）。

## 解决什么痛点

- GB/T 7714 规则细节多（文献类型标识、电子文献引用日期、3 位以上作者写法），
  几十条文献里错一处很难肉眼发现
- 批量验证链接时，403/412/429/超时 **不等于**链接失效——很多是被反爬拦截，
  浏览器里明明能打开。本工具的脚本把结果分三桶：可访问 / 疑似反爬（需浏览器复核）/
  疑似失效（DNS、证书等硬错误），避免误删好链接

## 快速开始

```bash
# 每行一个：URL / DOI / PMID / PMC 编号，自动判别类型
python3 scripts/check_refs.py refs.txt

# JSON 输入可显式指定类型
python3 scripts/check_refs.py refs.json --timeout 20 --workers 8
```

退出码：0 = 无明确失效项；1 = 存在失效项。
**零依赖**：只用 Python 3 标准库 + 系统 curl。

## 作为 Agent Skill 使用

把本目录放进你的 skills 目录（如 `~/.workbuddy/skills/`、`.claude/skills/`）。
Agent 会在「按国标改参考文献」「核对这批链接」等场景自动加载 `SKILL.md`，
其中包含：

- GB/T 7714-2015 著录要点与常见类型标识速查表
- 「疑似反爬 vs 疑似失效」判定逻辑与常见站点访问特性
  （卫健委 412、万方、知网、NEJM/Lancet 付费墙）
- 程序化写入 + 回读校验工艺（must_have / bads 清单），防长列表写入字符错乱
- Zotero CSL 样式调整指引（含「去掉 [引用日期] 是否合规」的权衡提示）
- 交稿前 8 项检查清单

## 说明

GB/T 7714-2015 是**推荐性**国家标准，具体格式以目标期刊/学校模板为准。
本工具负责「规范 + 核验 + 防写入错乱」，不替官方做格式裁决。
